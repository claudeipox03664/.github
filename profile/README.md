<p>选动态住宅 IP 时最常被忽略的一点：参数不是越"强"越好，而是要跟业务对上。轮换太快，账号每次看到新地址，行为轨迹碎成片；轮换太慢，批量任务的效率又上不去。地区选到城市级，成本翻倍却未必用得上。并发开到上限，延迟反而先崩。这篇按参数逐个说明含义、常见取值和取值依据，最后给一行可以直接抄的配置。</p>

<h2>一、轮换周期：账号看到新地址的频率</h2>
<p>这个参数决定同一个会话在多长时间内保持同一个出口。它不是"越快越像真人"，恰恰相反，过快的轮换会让行为看起来更像机器。</p>
<h3>按请求轮换只适合无状态任务</h3>
<p>每次请求换一个地址，适合采集、比价这类不需要连续性的工作。一旦涉及登录、下单、多步表单，按请求轮换基本必挂，因为第二步和第一步不在同一个会话里。</p>
<h3>登录类场景建议粘性 10 到 30 分钟</h3>
<p>一次完整的登录加浏览，通常在十分钟内结束。把粘性设在这个区间之上，能保证整个操作在一个出口内完成。设得太长（比如几小时）也没必要，反而增加单条线的负载。</p>

<h2>二、地区粒度：国家、城市还是运营商</h2>
<p>地区参数有三个层级，价格和可用性差别很大，选错层级是最常见的浪费。</p>
<h3>国家级够用的场景占多数</h3>
<p>内容、语言、支付方式的国家级差异最明显，城市级差异只在少数业务里成立。先按国家级配置跑一周，确认确实存在城市级差异，再下沉，不要一上来就买最细的。</p>
<h3>运营商维度常被忽略但影响不小</h3>
<p>同一城市里，家宽和移动网络的出口特征不同。有些站点对移动网络更宽容，有些对家宽更敏感。如果目标站点有明确的运营商偏好，这个维度比城市更值得调。</p>

<h2>三、并发与连接数：两个容易混淆的上限</h2>
<p>报价单上的"并发"通常指同时活跃的出口数，"连接数"指单条出口上能建多少 TCP 连接。两个数字限制的是不同东西，混着看会得出错误结论。</p>

<h3>并发决定吞吐上限，连接数决定单线能力</h3>
<p>10 个并发、每个 50 连接，理论上是 500 条通道，但实际受目标站点限流影响，能用到一半就不错。压测时按梯度加，找到延迟开始抬升的那个点，那个点才是可用值。</p>
<h3>留 30% 余量给突发</h3>
<p>按峰值配置并发，等于没有余量。任何一次重试风暴都会把池占满，导致正常请求排队。按峰值的 1.3 倍配置，多出来的部分成本不高，但能避免雪崩。</p>

<h2>四、会话保持：粘性时长怎么定</h2>
<p>会话保持和轮换周期是一对参数：前者保证一段时间的连续性，后者决定这段时间有多长。两个都设，才能得到想要的行为。</p>
<h3>按业务最长单次操作时长来定</h3>
<p>统计一次完整操作从开始到结束的耗时分布，取 P90 作为粘性时长。这样九成的操作能在一个会话内完成，剩下一成即使被切换也能通过重试恢复。</p>
<h3>会话失效要有兜底</h3>
<p>会话可能因为线路故障提前结束，这时候请求会突然换到一个新地址。代码里要能识别这种情况（比如返回的地址指纹变了），并主动重新走一遍初始化流程，而不是硬着头皮继续。</p>

<h2>常见问答</h2>
<h3>轮换周期设得越短，是不是越不容易被识别？</h3>
<p>答：相反。短时间内频繁更换出口，会让行为轨迹变得不连续，反而更容易触发验证。轮换频率应该匹配业务的自然节奏，而不是追求"看起来随机"。</p>
<h3>并发数买少了会怎样？</h3>
<p>答：请求会排队，表现为延迟升高而不是直接报错，比较难察觉。如果发现 P95 延迟随业务量线性上升，先看并发是不是打满了。</p>
<h3>城市级地区一定要买吗？</h3>
<p>答：只在目标内容确实存在城市差异时才需要。多数情况下国家级就够，多花钱买城市级但业务用不上，是常见的预算浪费。</p>
<h3>参数调优要一次改几个？</h3>
<p>答：一次一个。同时改三个参数，出问题时无法归因，只能全部回滚重来。每次改动后至少观察一天再动下一个。</p>

<h2>合规提示</h2>
<p>参数配置应用于合法授权的业务场景，遵守服务商条款与目标平台的服务协议，本文不涉及规避平台风控的内容。</p>
<p>会话日志可能包含访问路径等敏感信息，应按业务需要最小化采集并设置保留期限。</p>
<p>文中取值区间为常见实践的经验范围，仅供参考，具体应以压测结果与合同约定为准。</p>
